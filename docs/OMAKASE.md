## The service: how to read this file

`BUFFET.md` §1 gave the game its kitchen: asset classes are *stations*, a *plate* is a portfolio, the *sneeze guard* is compliance, the salad bar is bonds and the dessert bar is crypto. This file keeps those names for the parts of the game, the developers' words alone, which the game never says, its title and its tagline excepted (`BD-2`, amended 2026-10-15); and it adds the words a kitchen uses for the work itself, so that a reader who knows a restaurant knows the roadmap:

- **The house** is the repository: its terms, its names, its pins, its releases.
- **Mise en place** is everything in its place before the doors open: the kit copied, the layout decided, the first measurements taken. It is also the instruments the kitchen keeps beside the line while it cooks: the game written by hand, the floors, the playtest session.
- **A course** is a version. Eight courses, 0 to 7, each a game a diner can play alone from the exam to an ending, each composed on the courses before it, which it may amend (`BD-1`). A course served is a release (`HOUSE.5`).
- **A dish** is an item: one mechanic, built for one course. A dish served across courses is built in **slices**, one a course, and each course's list names the slice it takes.
- **The pass** is where a dish is checked before it leaves the kitchen, and the word is Alonzo's own: the pass expands a source into the cartridge the engine loads (`SPEC.md` §7.8). Nothing goes to the table that has not been through it, the game by hand holding every frame and the checks green.
- **The tasting** is a course's oracle and the owner's hand test. **The playtest pass** is the course played as a person plays it, every frame held and each phase timed.
- **Service** is the release: the tag, the notes, the page deployed.
- **The spike** is where a finished ticket goes, `SPIKE.md`.
- **The ratchet** is how a pattern moves. Written twice in Buffet, it goes into Buffet's own library, `src/kitchen.vla`. Written alike by a second cartridge, it goes into Alonzo's kit by a pull request there, the copy, `src/common.vla`, following at the next pin, every cartridge then expanding to its bytes unchanged. It enters the engine or the language only on a measurement and a second client. The market generator, the ladder, the picker and the lattice are Buffet's own until another cartridge writes one.
- **The three plates** are Whitworth's (`Frazaro/docs/metameta/METAMETALISP4.md` §2): the cartridge, the game written by hand in Rust (`MISE.2`) and the game written a third time in the page's JavaScript are rubbed against one another until every frame agrees, and no outside standard is needed for that. What the plates cannot tell is whether the game is any good, which is why every course ends with a person at the table.

## The standing decisions: the kitchen's rules

*Declared first, before any dish uses them, for the reason `METAMETALISP4.md` §0 and §1 give: a decision a team runs on but never writes down is re-derived, slightly differently, at every occasion that needs it, and a decision written down expands at every call site whether anyone remembers it or not. Numbered so an item can cite them, each with its reason attached so that a later hand can tell doctrine from accident. `BD-2`, `BD-4` and `BD-6` are the owner's words from `BUFFET.md`; the rest are proposed (rec), to be adopted, amended or struck by the owner at `COURSE.0`'s approval, and until then they bind this file's items and nothing else. The engine's rules cross the road under their own numbers and are never re-minted: `AD-6` (everything the engine holds is a cell), `AD-7` (the step computes values and never formulas), `SD-13` (no outbound call, ever), the `GENSYM` veto, and the kit's ratchet in Alonzo's `ROADMAP.md` under "The order, and why".*

- **`BD-1`. Every course is a game, composed on the courses before it.** A course is a tranche of independently playable features, served only when the game it makes is playable from the exam to an ending, with its replay golden, its describe golden and the owner's hand test; a later course adds features to the game the earlier ones made playable, and may change what they built, as any item of this file may be amended or expanded at any point. A change that breaks what an earlier course built, a recorded replay among it, is made only when it must be, and handled as it comes. No course is frozen, and neither the game's code nor its content records the course a thing arrived with: this file's items carry that. *Why:* it is all the same game. *(Amended 2026-10-15, the owner, at `MENU.2`'s close: "BD-1 was intended to be a composability rule in which later version of the game added features to already-playable games, but that doesn't mean that earlier version/courses are frozen forever. That unnecessarily Draconaian. It's all the same game. If we want to change something in course 0 while building course 4, then that should be allowed. Obviously we don't want breaking changes unless absolutely necessary, but even those can be handled on an as-needed basis." And: "Courses don't need to be versioned inside the code. The roadmap items are already the course-versioned features which can either be amended or expanded at any point in development. Courses represent tranches of independently-playable features, not code-freeze points." The rule had read "a course changes no course before it": the earlier course byte for byte what it was, proved by the pass expanding its frozen source to its frozen cartridge (`MISE.1`'s second slice, struck with the reading), its bytes changed only by a dated fix of its own, and every replay ever recorded playing on; and each content row carried the course that added it, its vintage, struck the same day.)*
- **`BD-2`. Funny is a requirement (owner).** The game is fun insofar as it is funny, jokes all the way down. Every player-visible string is a row of a data sheet with a chance at a joke; the voice is `BUFFET.md` §2's deadpan compliance; the rules are its rules, punch up, fictional names, clarity first, strings as data, PG-13. A string with no joke has a reason written beside it. *(Amended 2026-10-15, the owner, at `FRONT.1`'s scoping: "No kitchen names anywhere. The kitchen analogy is for the dev documents only. The title, "Buffet", is the extent of the kitchen terminology in the game, because the game should look and feel like a fund manager's workbook with the humor limited to financial and economic winks and jokes throughout." So every string a player sees, a sheet's name, a tab's label, a panel's title, the manifest's notes, is a fund manager's word, and every joke a financial or an economic one; the kitchen's words name the work in this file, the ledger and the code's comments, and nothing the player sees. One more exception, the owner the same day: the tagline stays in the game's notes, "because it's the game's tagline and punchline", spelled as the README's title spells it, "All You Can Sheet".)* *(Clarified 2026-10-15, the owner, answering the flag on the exam's "omelettes" at `MENU.5`'s close: "subtle kitchen winks are also fine, but forced puns or metaphors are usually weak comedy". So the rule binds names: no sheet, tab, panel or label a player reads takes a kitchen word; a joke may wink at the kitchen, and a forced pun is weak comedy whatever its subject. "Food for thought", a general idiom, is no wink at all.)*
- **`BD-3`. The market is exogenous, deterministic and open.** The market's path is a pure function of the seed, the difficulty and the scenario; the dice are a Park and Miller cell seeded from `Clock!B3` and nothing else is random; the player's orders never move a price (slippage is a cost, not a path); and the model is a sheet anyone may read, so the open-book problem of `BUFFET.md` §5 is a feature by design, and a score is alpha over a benchmark on the same seed (`CRITIC.1`), never a raw net worth. *Why:* a replay replays the market, scores on different seeds compare, and nothing has to be hidden from a player who can open every cell (`AD-6`).
- **`BD-4`. Checkers first, chess one license at a time (owner).** The first five minutes need nothing a license has not unlocked; each license is an exam and a layer of the interface; a mechanic that would frighten a first player stands behind a license and never on the opening screen. Progressive disclosure is the product.
- **`BD-5`. Toy models, labeled.** Every simplification is a row of the *Things this game gets wrong* sheet (`MENU.5`); the game is not advice and says so; no real data, no feed, no real ticker's price (`SD-13`); no real money, ever; a concept card is read by a finance educator before it ships, since "tutorial" implies correctness. *Why:* a simplification labeled is a lesson and a simplification hidden is a liability (`BUFFET.md` §12). *(Amended 2026-10-15 at `MENU.5`, its scoping approved by the owner, the sheet's name the owner's: the sheet is `Caveats`, `src/content/caveats.vla`, the one content sheet shown among the tabs, after the model's sheets, since a player reads it whole; its first row is the plain statement that the game is not advice, its joke beside it, which the certificate quotes (`GUARD.1`); and a dish that brings a simplification brings its caveat in its own commit, its scoping naming the row. Lovelace Lavender, the arcade's primary (owner's standing rule for the house's games).** Lovelace Lavender is the brand's primary color, held the same across Alonzo's games so that the arcade has one look; other colors stand beside it, red and green among them. *(Amended 2026-10-14, the owner: "I recant my hard constraint that Lovelace Lavender is the *only* color in the entire game; I just want Lovelace Lavender to be a consistent branding primary color throughout Alonzo's games to provide a consistent look across the arcade." - **`BD-7`. The calendar is the market's clock, and only the calendar reads the frame.** A frame is two minutes of the market's time, thirty an hour, so that the manifest's rate of thirty passes an hour a second (`POT.10`); the market trades from the opening bell, 9:30, to the closing bell, 16:00, Monday to Friday; prices move at the session's marks, the opening bell and each half hour to the closing bell, and the dice, fees, timers and events at a day's first frame, and nothing moves at any other frame; a person's act is answered at the next frame. Held by a test that no formula outside the Day sheet reads the frame, the time to the minute or its twin, and by `describe`'s census computing no shape every frame, `(every-frame 0)`. (*Restated 2026-10-16 at `POT.10`'s approval, the owner's words: "The game should run at one real-world second per hour of in-game market play. I also think the market should have trading hours and non-trading hours". It had read: "The market day is the market's clock ... - **`BD-8`. State is a cell, and the cartridge never writes code.** A position, a balance, a timer, a license is formula state over its twin (the kit's `count`, `hold` and `since`) or a value the Write sheet puts there (`put`), and never a thing the host keeps (`AD-6`); the cartridge's step writes values and never formulas (`AD-7`); the one place a formula enters at run time is a person's own act on the Strategy sheet (`RECIPE.1`), recorded by the replay as an edit. Strings are data; a picker is `CHOOSE` over references, generated by a macro.
- **`BD-9`. Two pockets, and no switch moves money.** The firm's capital and the partner's wealth are separate cells; the Personal/Firm selector changes which pocket an order funds and what the plate shows, and never a balance; every transfer, draw or contribution is a row of the ledger with the pocket it left and the pocket it entered. *Why:* a selector that moved money would be state the replay could not read off the ledger.
- **`BD-10`. Nothing leaves the kitchen untasted.** The game written by hand in Rust holds every frame of every course (`MISE.2`); where mathematics has a closed form, the cells are held to it to the last bit or a stated tolerance; a course has a replay golden and a describe golden; the playtest pass (Alonzo's `ROADMAP.md`, the owner's name of 2026-10-12) runs before a course is served; an accelerator, a kit hoist or a language ask is made with a measurement in hand and never before. *Why:* Whitworth's plates, above; and `METAMETALISP4.md` §5's field mark, that the real instrument keeps acquiring specimens, which is what a course is.

## The order of service, and why

**The rule.** Work is ranked by its cost of delay, and what is dearest to undo goes first (`METAMETALISP4.md` §3): a layout, a name, a number in a contract, a sheet's address every later formula reads. An instrument earns its place before a dish by the three tests of §5: something named gets dearer each day it is missing (rising cost), the instrument is smaller than the work it unlocks (proportion), and the kitchen is its first user this week (dogfood). An instrument with no specimen this course waits for the course that has one, since the microscope is justified by the dissection and only by it (§8). And the first version of anything is made badly on purpose and improved in use (§2, §Ω): a button before a plate, four rungs as rows before a ladder, one panel before a tab strip, the market moving on the page before a single order can be placed.

**The courses.** The sequence is `BUFFET.md` §13's, kept because each course isolates one cost for the engine and one decision for the player, and what each course builds is what makes the next one cheap:

## 🔪 MISE EN PLACE: before the doors open

*What stands ready before the first row of the game is written, in order. Each line passes the three tests or says which course it waits for.*

**The three tests, applied.** The founding and the pins (`HOUSE.1`, `HOUSE.2`) are the dearest things to change later and the cheapest now, and they are built.
